# フロントエンド画面設計

## 技術スタック

| 項目 | 選定 | 理由 |
|------|------|------|
| ベース | React 18 + Vite | 要件確定済み |
| 言語 | TypeScript | 型安全のため |
| ルーティング | React Router v6 | 標準的 |
| 状態管理（サーバー状態） | TanStack Query (React Query) v5 | キャッシュ・再フェッチを宣言的に |
| 状態管理（クライアント状態） | Zustand | 必要箇所のみ。Reduxは過剰 |
| HTTPクライアント | fetch API + 薄いラッパー | axios は不要 |
| UIフレームワーク | **MUI (Material-UI) v5** | 豊富なコンポーネント、Material Design準拠 |
| スタイリング | MUI の `sx` プロップ + Emotion | MUI標準 |
| HLS再生 | hls.js（Chrome）/ Safari ネイティブ | 自動切替 |
| アイコン | @mui/icons-material | MUIと統合 |
| フォーム | React Hook Form + zod | バリデーション込み |
| 日付 | date-fns + date-fns-tz | JST扱いやすい |
| 日付ピッカー | @mui/x-date-pickers | MUIとの統合 |

## 画面構成

```
/login                  ログイン画面（Google OAuth）
/                       番組表（ホーム）
/registrations          登録一覧
/library                録音ライブラリ
/library/:title         番組ごとの各回一覧
/player/:historyId      再生画面
/history                ダウンロード履歴
/settings               設定（エリア・放送局表示）
```

ヘッダーメニュー（認証済みのみ表示）:
- 番組表 / 登録一覧 / ライブラリ / 履歴(失敗バッジ付き) / 設定 / ログアウト

## 主要画面詳細

### 番組表画面 (`/`)

```
┌──────────────────────────────────────────────────────────┐
│ [< 4/23] [4/24 (金)] [4/25 >]  エリア:[東京▼] 検索:[___] │
├──────────────────────────────────────────────────────────┤
│       │ TBS       │ ニッポン放送 │ 文化放送  │ J-WAVE   │
│  5:00 │ ●朝の番組 │ ニュース    │ ...       │ ...      │
│  6:00 │           │ 朝ワイド     │           │          │
│  7:00 │ ★モーニング│ ★(登録済)  │ ...       │ ...      │
│  ...  │           │              │           │          │
│ 25:00 │ ●深夜枠   │ ●ANN        │           │          │
│ 26:00 │           │              │           │          │
└──────────────────────────────────────────────────────────┘
凡例: ●過去（DL可）  ☆未来（DL予約可）  ★登録済
```

#### 仕様
- 縦軸: 5:00〜29:00（25時制表示。深夜2時 = 26:00）
- 横軸: エリアの全放送局（user_station_visibility で表示制御）
- セル背景色で「過去/未来」を区別
- 登録済みは枠線色＋アイコンで強調
- 番組クリック → モーダルで詳細表示＆登録ボタン

#### レスポンシブ切替

画面幅で表示形式を自動切替する（Tailwind のブレークポイントを利用）：

| 画面幅 | 表示形式 |
|--------|---------|
| `lg` 以上（≥1200px、MUI 規定） | **グリッド表示**（縦=時刻 × 横=放送局） |
| `lg` 未満（< 1200px） | **リスト表示**（放送局を縦並び、各局の番組をカード表示） |

※ MUI のブレークポイント `useMediaQuery(theme.breakpoints.up('lg'))` で切替判定

##### グリッド表示（PC向け）
- 縦軸: 5:00〜29:00、各セルは番組ブロック
- 横軸: エリアの全放送局（user_station_visibility で表示制御）
- 番組ブロック高さ = 放送時間に比例

##### リスト表示（スマホ・タブレット向け）
- 横スクロールタブで放送局を切替（または上部に放送局アイコン横スクロール）
- 選択中の放送局の番組を時刻順カードで縦並び表示
- カード: 番組名 / 時刻 / 出演者 / 登録ボタン

##### 共通
- 番組クリック → モーダル（PC）or ボトムシート（スマホ）で詳細＋登録ボタン
- 過去/未来の区別はセル/カードの背景色で表現
- 登録済みは枠線色＋アイコンで強調

##### 実装メモ
- 切替は MUI の `useMediaQuery(theme.breakpoints.up('lg'))` フックで分岐
- 同じデータソース（`GET /api/programs`）を共有し、表示コンポーネントだけ分岐
- グリッド/リスト各コンポーネントは別ファイルに分離（`ProgramGrid.tsx` / `ProgramList.tsx`）

#### データ取得
- `GET /api/programs?areaId=&date=` を TanStack Query でキャッシュ
- 日付・エリア変更で自動リフェッチ

- 番組名グルーピング表示（カード or リスト）

- 放送日時降順
- 各回: 放送日時 / 出演者 / 再生ボタン / 削除ボタン
- 削除は確認ダイアログ＋期限切れ警告（API レスポンスの `reDownloadable` で判定）

### 再生画面 (`/player/:historyId`)

```
┌──────────────────────────────────────────────────┐
│ オールナイトニッポン                              │
│ 2026/4/24(金) 25:00〜27:00                        │
│ 出演: ...                                         │
│                                                   │
│  ◀◀  ▶  ▶▶                                       │
│  [============▼=================]  45:23 / 2:00:00│
│                                                   │
│  -10s  +30s                                       │
└──────────────────────────────────────────────────┘
```

#### 仕様
- hls.js でストリーミング再生
- レジューム: マウント時に `GET /api/recordings/:id/playback-position` で位置取得→seek
- 5秒間隔で `PUT /api/recordings/:id/playback-position` を投げる（再生中のみ）
- 一時停止・終了時にも保存
- バックボタンで戻ったら直前の位置から再開可能

#### HLS プレイヤー実装
```typescript
import Hls from 'hls.js';

if (Hls.isSupported()) {
  const hls = new Hls();
  hls.loadSource(hlsUrl);
  hls.attachMedia(videoRef.current);
} else if (videoRef.current.canPlayType('application/vnd.apple.mpegurl')) {
  videoRef.current.src = hlsUrl; // Safari ネイティブ
}
```

### 履歴画面 (`/history`)

- ステータスフィルタ: 全て / 成功 / 失敗 / 期限切れ
- 失敗・期限切れに警告アイコン
- 各行に「履歴を削除」ボタン

#### 削除確認ダイアログ文言

履歴のステータスとタイムフリー期限内かで文言を切替（要件 F1 通り）：

| 履歴の状態 | 確認ダイアログ文言 |
|-----------|------------------|
| 期限切れ（`EXPIRED` または期限超過の `SUCCESS`） | **「この番組は再ダウンロードできません。」**＋削除確認 |
| 期限内の成功 / 失敗 | 「履歴を削除すると次回バッチで再ダウンロード対象に戻ります。」＋削除確認 |

判定ロジック:
- `status === 'EXPIRED'` → 期限切れ文言
- `status === 'SUCCESS'` で `now > expiresAt(broadcast_start_at)` → 期限切れ文言
- それ以外 → 通常文言

### 設定画面 (`/settings`)

**設定画面で扱う項目はエリア・放送局表示のみ**（要件 F1「設定画面の対象はエリア・放送局の設定のみ。その他の設定は環境変数・設定ファイルで管理する」）。SMTP設定・JWT・パス設定など運用系設定は画面に出さない。

- エリア選択（プルダウン or リスト）
  - 変更時は確認ダイアログ「番組表を再取得します」
  - 変更後、F4 が走る → 進捗バー表示
- 放送局表示/非表示の切替（エリア内全局のチェックボックス一覧）

---

## バッジ表示

- ヘッダーの「履歴」メニュー横に失敗・期限切れ件数を赤バッジで表示
- 取得方法: `GET /api/histories/badge` を **30秒間隔でポーリング**（TanStack Query の `refetchInterval`）
- WebSocket は採用しない（個人利用・更新頻度低のためポーリングで十分）

---

## バッチ手動実行UI

設定画面の下部 or ヘッダーの「⚙️」メニューに：

```
[F4: 番組表取得]   [実行中...]
[F2: ダウンロード] [実行]
[F4 → F2 一括]    [実行]

オプション:
□ 強制実行（成功済みも再DL）
日付指定: [____-__-__]
```

- 実行中は別タブの GET /api/batch/executions/{id} をポーリングして進捗表示

## ビルド・配信

- Vite で `npm run build` → `dist/`
- Docker ビルド時に `dist/` を nginx コンテナにコピー
- Nginx は `/` で `dist/` の静的配信、`/api/*` は Spring Boot にプロキシ
