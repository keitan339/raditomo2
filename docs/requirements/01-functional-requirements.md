# 機能要件定義

## 概要

ラジコ（radiko）のタイムフリー番組をダウンロードし、ダウンロードした録音ファイルを再生するアプリケーション。

## 前提・制約

- ラジコのフリー会員を対象とする（プレミアム会員のエリアフリーは非対応）
- ラジコのタイムフリーAPI仕様（2026年1月変更）：プレイリストURLが `smartstream.ne.jp` に移行し、チャンク分割取得方式となった。通常の取得では等倍速（1時間番組≒1時間）となるが、チャンク並列取得による高速化が可能
- タイムフリーの制限：過去1週間の番組のみダウンロード可能
  - ラジコの1日の区切りは午前5時（5:00〜翌5:00が1日）
  - 放送日から7日間が対象で、8日目の午前5時に聴取不可となる
- 個人利用を想定（利用者は自分1人。ただし設計上は複数アカウントに対応する）
- システム全体で日本標準時（JST / Asia/Tokyo）を使用する

## 機能一覧

### F1: ダウンロード登録

- 事前取得済みの番組表データ（DB）を表示する（画面表示時にラジコへ都度アクセスしない）
  - 過去の番組表（タイムフリー対象期間）と、今日を含む未来の番組表の両方を表示できる
  - 日付を選択して切り替えられる
  - 過去の番組表か、今日を含む未来の番組表かが視覚的に区別できる
  - 1日の区切りは午前5時とする（5:00〜翌5:00が1日。深夜1時の番組は前日の25時として表示）
- エリアを選択すると、そのエリアの全放送局の番組表を表示する
  - 初回利用時にエリアを選択する
  - 選択したエリアは保存され、次回以降は選択不要
  - 設定画面からエリアを変更できる（設定画面の対象はエリア・放送局の設定のみ。その他の設定は環境変数・設定ファイルで管理する）
  - エリア変更時は、新エリアの番組表を即座に全範囲取得する
  - 取得が失敗した場合、エリア変更は保存し、番組表は次回F4実行時に補完する（画面にエラーを表示する）
  - 放送局ごとに表示/非表示を切り替えられる（設定は保存される）
  - 非表示にした放送局を再度表示に戻せる
- 番組表上で、ダウンロード登録済みの番組が視覚的に区別できる
- キーワードで番組を検索できる（番組タイトル・出演者を横断的に検索）
- 番組を選択し、ダウンロード登録する（過去・未来どちらの番組でも可）
  - 登録データ：放送局・番組名・放送開始日時・放送終了日時
  - 番組選択時にも、その番組が登録済みかどうかを表示する
  - 登録時に「一回限り」か「毎週（定期ダウンロード）」かを選択できる
  - 一回限り：その番組のみをダウンロード対象にする（ダウンロード完了後、登録は自動的に「完了」ステータスになる。タイムフリー期限切れでダウンロードできなかった場合は「期限切れ」ステータスになる）
  - 毎週：F2バッチ実行時に、登録された放送局＋番組名＋曜日でDB上の番組表を検索し、該当する番組を毎週自動的にダウンロードする
- 同じ番組の重複登録は禁止する（既に登録済みの番組は登録済みとして表示し、再登録できないようにする）
  - 一回限り：放送局＋放送開始日時が同一の場合に重複と判定する
  - 毎週：放送局＋番組名＋曜日が同一の場合に重複と判定する
- ダウンロード登録の解除時、既にダウンロード済みのファイルは削除せずそのまま残す
- ダウンロード履歴を確認できる（いつ・何の番組をダウンロードしたか、失敗したか。履歴は無期限に保持する）
  - 履歴のステータス（成功/失敗/期限切れ）を個別に削除できる（削除した番組はF2の次回実行時にダウンロード対象に戻る）
  - タイムフリー期限切れの番組の履歴を削除する際は「再ダウンロードできません」と警告を表示する（削除自体はブロックしない）
- ダウンロード登録一覧を確認できる（曜日ごとに登録してある番組一覧の表示、登録の解除）
- Web画面からF4（番組表取得）・F2（ダウンロード）を手動実行できる
  - F4単体実行、F2単体実行、F4→F2一括実行を選択できる
  - F2実行時はCLIと同じオプション（日付指定・強制フラグ）を指定できる
  - 非同期で実行し、完了を待ち合わせない（実行中の状態は画面上で確認できる）

### F2: タイムフリーダウンロード

- F4（番組表取得バッチ）完了後に自動実行される（F4で一部失敗があった場合も、DB上の最新データで実行する）
- 1番組ずつ直列にダウンロードする
  - ダウンロード失敗時はその場で最大3回リトライする。3回失敗したらスキップして次の番組に進む
- ダウンロード対象の判定：ダウンロード登録情報 × DB上の番組表 × ダウンロード履歴を動的に照合して決定する（予約レコードは生成しない）
  - 「一回限り」登録：放送局＋放送開始日時で番組表を検索し、ダウンロード履歴に成功記録がない番組を対象とする
  - 「毎週」登録：放送局＋番組名＋曜日で番組表を検索し、ダウンロード履歴に成功記録がない番組を対象とする
  - 共通条件：すでに放送が完了しており、かつタイムフリー対象期間内（放送日から7日間、8日目の午前5時まで）であること
- タイムフリー期限切れでダウンロードできなかった番組は「期限切れ」ステータスで履歴に記録し、対象から除外する
  - 期限切れもダウンロード失敗と同様にバッジ＋メールで通知する
- 「毎週」登録のダウンロード対象マッチング手順（DB上の番組表を参照。「一回限り」登録は放送開始日時で直接特定するため本手順は適用しない）
  1. 放送局＋登録時の放送開始日時で番組表を検索し、該当する番組が登録した番組名と一致するかチェックする
  2. 一致した場合：そのままダウンロードする
  3. 一致しない場合：同じ放送日（5:00〜翌5:00）内で同じ番組名の番組を検索し、見つかればその時刻でダウンロードする
  4. 番組名が見つからない場合：登録時の放送開始日時・放送終了日時でダウンロードし、DB上の該当時間帯に放送されている番組名で保存する
- 対象番組をラジコのタイムフリーからダウンロードし、MP3形式で保存する
  - チャンク並列取得により高速ダウンロードを実現する（等倍速では運用に支障があるため必須）
- ダウンロード完了後、ffmpegでHLSセグメント（.m3u8 + .ts）に事前変換する（再生時のレスポンス向上のため）
  - HLS変換が失敗した場合はMP3も削除し、全体を「ダウンロード失敗」として扱う（翌日リトライ対象になる）
- MP3ファイルの保存先は設定で変更可能とする
- 保存先のフォルダ構成（アカウントごとにディレクトリを分離し、MP3とHLSをトップレベルで分離する）
  - MP3: {base_path}/{account_id}/mp3/{番組名}/{番組名}_{YYYYMMDD-HHMM}.mp3
  - HLS: {base_path}/{account_id}/hls/{番組名}/{YYYYMMDD-HHMM}/ 配下に .m3u8 と .ts を配置
  - 例:
    - /data/recordings/user123/mp3/オールナイトニッポン/オールナイトニッポン_20260222-0100.mp3
    - /data/recordings/user123/hls/オールナイトニッポン/20260222-0100/playlist.m3u8
- MP3ファイルに以下のID3タグを付与する（番組名はDB上の最新の番組表データを使用）
  - Title: 番組名＋放送開始日時（例: オールナイトニッポン_20260222-0100）
  - Artist: 出演者名
  - Album: 番組名
  - Album Artist: 放送局の和名
  - Year: 放送開始年（YYYY）
  - Date: 放送開始日時（YYYYMMDD-HHMM）
  - Duration: 放送時間
- リトライ時は前回失敗の部分ファイル（MP3・HLS）を削除してから再ダウンロードする
- ダウンロード結果（成功/失敗/期限切れ）を履歴に記録する
- CLI形式での手動実行にも対応する（番組表はDBの既存データを使用）
  - オプションなし：自動実行と同じ（全未完了番組を処理）
  - 日付指定：指定した放送日（5:00〜翌5:00）の登録番組のみを対象とする（例: 20260424 → 4/24 5:00〜4/25 5:00）
  - 強制フラグ：ダウンロード成功済みの番組でも再ダウンロード（上書き）する
  - F4 → F2 一括実行：番組表取得後にダウンロードも実行する
- ダウンロード失敗・期限切れの通知
  - Web画面上にダウンロード失敗・期限切れ件数のバッジを表示する
  - バッチ実行ごとに、その日の失敗・期限切れをまとめてメールで通知する（Gmail SMTP経由。通知先はログインしたGoogleアカウントのメールアドレス）
  - 同じ番組が連日失敗している場合も毎日通知する

### F3: 録音ファイルの再生

- ダウンロード済みの番組一覧を番組名ごとにグルーピングして表示する
  - 番組名の一覧から選択すると、その番組の各回（放送日時順）が表示される
- 番組名での検索、放送日時でのソートができる
- 番組を選択して再生する
- 録音ファイルを削除できる（主にタイムフリー期限切れで再ダウンロード不可の古い録音の整理を想定）
  - 削除前に確認ダイアログを表示する
  - 削除時はMP3ファイルとHLSセグメントの両方を削除する
  - ダウンロード履歴の記録は削除せず保持する（ファイル削除後もダウンロード済みとして扱い、F2の再ダウンロード対象にはしない）
- 録音ファイルをHLS形式でストリーミング再生する
- 基本的な再生操作（再生 / 停止 / シーク）ができる
- レジューム再生：番組ごとに再生位置をサーバー側に保存し、次回再生時に途中から再開できる
  - 再生位置は複数の端末間で共有される（例: PCで途中まで聴いた番組をスマホで続きから再生できる）

### F4: 番組表取得バッチ

- スケジューラーにより毎朝5:30に自動実行し、対象エリアの全放送局の番組表をラジコから取得してDBに保存する
  - 番組表取得完了後（一部失敗があっても）、F2（タイムフリーダウンロード）を自動的に開始する
- 取得対象：ラジコが公開している全範囲（過去1週間＋今日以降）の番組表を毎回取得する
  - 毎回全範囲を取得することで、過去に失敗した日や放送局のデータ欠落を自然に補完する
  - 取得したデータでDB上の既存データを上書き更新する
- 取得したXMLをパースし、番組情報を構造化してDBに保存する
- 取得した生のXMLもファイルとして保存する（XMLの形式変更時にパースエラーの原因を比較・調査できるようにするため。無期限に保持する）
  - 同じ日・放送局のXMLが既に存在する場合は上書き保存する
- 放送局単位で取得・パースを行い、一部放送局が失敗しても成功分はDBに保存し、F2の実行は止めない
- 取得失敗・パースエラー発生時はバッチ完了後にまとめてバッジ＋メールで通知する（通知内容：失敗した日付・放送局の一覧。詳細はサーバーログで確認）
- F1（ダウンロード登録）およびF2（タイムフリーダウンロード）はこのDBデータを参照する
- CLI形式での手動実行にも対応する（オプション不要。自動実行と同じく全範囲を取得・更新する）
  - F4単体実行（番組表取得のみ）
  - F4 → F2 一括実行（番組表取得後にダウンロードも実行）

### F5: 認証

- Google OAuth 2.0 によるログイン機能を設け、認証済みユーザーのみアプリにアクセスできる
- 許可リスト制：事前に登録されたGoogleアカウント（メールアドレス）のみログインを許可する
  - 許可リストの管理はCLIまたはDB直接操作で行う（管理画面は設けない）
- ログアウト機能を設ける
